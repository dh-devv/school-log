# 기술 의사결정(TDD)

이 문서는 기술과 제품 구조를 선택한 이유, 대안, 제약을 기록합니다. 여기서 TDD는 기술 의사결정 문서를 뜻하며 테스트 주도 개발과 구별합니다.

## 결정 1: 첫 버전부터 관리형 데이터베이스를 사용한다

- **상태:** 채택
- **결정:** 일정과 공지를 관리형 데이터베이스에 저장합니다. 브라우저가 읽을 공개 화면은 GitHub Pages에 게시할 수 있습니다.
- **이유:** 진행 중이거나 예정된 중요한 자료는 기기와 화면 배포에 의존하지 않고 보존되어야 합니다.
- **대안:** 정적 JSON 파일만 게시하거나 자체 서버와 데이터베이스를 운영합니다.
- **영향:** 데이터베이스와 백엔드의 요금, 장애, 백업·복구 및 접근 정책을 관리해야 합니다. 공급자는 비용과 운영 요건을 검토한 뒤 확정합니다.
- **변경 이력:** 이전의 정적 JSON 전용 결정은 데이터베이스 필수 요구에 따라 대체했습니다.

## 결정 2: 관리자용 웹 화면을 제공한다

- **상태:** 채택
- **결정:** 관리자가 인증 후 일정과 공지를 등록·수정·삭제합니다. 방문자의 공개 조회는 로그인 없이 제공합니다.
- **이유:** 자료를 유지하려면 관리자가 웹에서 변경 사항을 반영할 수 있어야 합니다.
- **대안:** 관리자만 데이터베이스 관리 도구에서 직접 자료를 수정합니다.
- **영향:** 관리자 계정 발급·회수, 서버 측 권한 검사와 직접 API 호출 시험이 첫 버전의 필수 작업입니다.

## 결정 3: 지난 자료는 우선 보관한다

- **상태:** 채택
- **결정:** 지난 일정은 자동 삭제하지 않고 보관합니다. 진행 중이거나 예정된 자료는 정상 운영 중 유지합니다.
- **이유:** 현재 필요한 정보를 지키면서 과거 자료를 성급히 삭제하지 않기 위해서입니다.
- **대안:** 종료 직후 삭제하거나 별도 보관소로 옮깁니다.
- **영향:** 저장 공간과 비용을 확인해야 합니다. 보존 기간과 자동 정리 여부는 학교와 별도로 결정합니다. 관리자의 의도적인 정정·삭제는 허용합니다.

## 결정 4: 첫 버전은 공개 승인된 자료만 다룬다

- **상태:** 채택
- **결정:** 승인 전 자료와 반별 비공개 정보는 첫 버전 데이터베이스에 넣지 않고, 승인된 자료만 공개 조회 API에 제공합니다.
- **이유:** 화면에서 숨기기만 하는 방식은 비공개 정보를 보호할 수 없습니다.
- **대안:** 미승인 또는 반별 정보를 함께 저장하고 접근 정책으로 구분합니다.
- **영향:** 학교와 별도의 승인 절차가 필요합니다. 반별 기능은 신원·역할·소속 검증을 포함한 별도 설계가 필요합니다.
- **범위:** 초안 저장·승인 상태 전환은 포함하지 않습니다. 학교에서 미승인 자료의 저장이 필요하다고 결정하면 공개 범위와 권한 정책부터 다시 설계합니다.

## 결정 5: 학년 필드는 첫 버전에서 제외한다

- **상태:** 채택
- **결정:** 학교 전체 공개 일정만 저장하고 학년 필드는 두지 않습니다.
- **이유:** 학년 정보의 공개 범위가 학교와 합의되지 않았습니다.
- **대안:** 학년 필드와 학년별 검색을 처음부터 추가합니다.
- **영향:** 학년별 검색은 학교가 공개를 승인하고 요구사항과 데이터 모델을 갱신한 뒤 추가합니다.

## 변경 및 검증 기록

- 이전 초안은 독립 모델 검토에서 지적한 공개 범위, 승인 절차와 자료 검증의 불명확성을 수정했습니다.
- 데이터베이스 필수 요구에 따라 정적 JSON 전용 설계를 대체하고, 관리자 웹 화면과 지난 자료 보관을 추가했습니다.
- 이번 변경의 독립 검토에서 날짜 경계, 백업·복구 담당과 목표, 관리자 권한 회수, 공개 상태, 오류 안내의 명확화가 제안되어 반영했습니다. 다만 초안 상태 추가 제안은 미승인 자료를 저장하지 않는 첫 버전 범위와 충돌하므로 반영하지 않았습니다.
- 학교의 공개 승인, 실제 권한·복구 시험은 별도로 진행해야 합니다. 모델의 검토는 실제 운영 검증을 대신하지 않습니다.
