# 제품 요구사항(PRD)

## 1. 제품 개요

School Log는 학교에서 공개를 승인한 일정과 공지사항을 한곳에서 조회하고 검색하는 웹 서비스입니다. 진행 중이거나 예정된 중요한 정보를 관리형 데이터베이스에 보존하고, 관리자가 웹 화면에서 관리합니다.

## 2. 사용자와 해결할 문제

| 사용자 | 첫 버전에서 할 수 있는 일 |
|---|---|
| 학생·교사·보호자 등 방문자 | 로그인 없이 공개 일정과 공지를 조회하고 날짜·종류로 검색 |
| 관리자 | 인증 후 공개 승인을 받은 일정과 공지를 등록·수정·삭제 |
| 교사 | 이메일 인증과 대표 관리자 승인 후 공개 자료를 등록·수정·삭제 |
| 대표 관리자 | 자료 관리와 교사 가입 승인 |

여러 경로로 흩어진 정보를 쉽게 찾고, 기기나 배포가 바뀌어도 필요한 일정이 사라지지 않도록 합니다.

## 3. 목표와 범위

### 첫 버전에 포함

- 공개 일정과 공지의 목록, 날짜별 조회, 종류별 검색
- 휴대전화와 컴퓨터에서 이용할 수 있는 반응형 화면
- 관리형 데이터베이스에 일정과 공지 저장
- 관리자 인증과 관리자용 웹 등록·수정·삭제 화면
- 교사 회원가입, 이메일 인증과 대표 관리자의 가입 승인
- 진행 중이거나 예정된 자료 보존 및 지난 자료의 우선 보관

### 첫 버전에서 제외

- 학생 계정, 반별 비공개 정보 및 반별 권한
- 누구나 가입 과정에서 관리자 권한을 얻는 기능
- 알림, 댓글, 개인화
- 학교의 공개 승인이 확인되지 않은 정보의 게시

## 4. 정보와 보존 원칙

- 방문자에게는 학교가 공개를 승인한 정보만 제공합니다. 첫 버전의 데이터베이스에는 반별 비공개 정보, 학생 이름 등 개인정보를 넣지 않습니다.
- 학교가 정한 시간대의 오늘 날짜를 기준으로, 종료일이 오늘과 같거나 이후인 일정은 아직 지나지 않은 일정입니다. 종료일이 오늘보다 이전이면 지난 일정입니다. 종료일이 없으면 시작일을 종료일로 봅니다.
- 진행 중이거나 예정된 자료는 정상 운영과 배포 과정에서 삭제되지 않아야 합니다. 정정 또는 삭제는 인증된 관리자가 의도적으로 수행할 수 있습니다.
- 지난 일정도 우선 보관하며 자동 삭제하지 않고 날짜와 종류로 조회할 수 있습니다. 보존 기간과 별도 보관 여부는 학교와 결정합니다.
- 일정과 공지는 날짜를 포함합니다. 게시 기간이 정해지지 않은 공지는 관리자가 종료일을 지정하지 않는 한 시작일의 일정으로 취급합니다.
- 자료 저장은 백업과 같은 뜻이 아닙니다. 운영 전 복구 목표와 백업·복구 절차를 정하고 복구 시험을 해야 합니다.

## 5. 개발 단계

| 단계 | 작업 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1. 운영 범위 합의 | 학교와 공개 범위, 승인 절차, 관리자 지정·회수, 보존·복구 목표를 정합니다. | 담당자와 절차가 문서로 확인됩니다. |
| 2. 구현 | 공개 조회 화면, 관리 화면, 관리형 백엔드와 데이터베이스를 구현합니다. | 인수 조건을 시험할 수 있는 버전이 준비됩니다. |
| 3. 검증 및 공개 | 자료 승인, 기능·권한·복구 시험을 마치고 사용자 피드백을 반영합니다. | 인수 조건을 충족하고 학교가 공개를 승인합니다. |
| 4. 반별 기능 검토 | 학생·교사 계정과 반별 권한, 개인정보 처리 및 비용을 별도로 설계합니다. | 요구사항·기술 설계·권한 검증 계획을 승인하기 전에는 운영하지 않습니다. |

## 6. 주요 사용 흐름

1. 방문자가 로그인 없이 공개 일정과 공지를 조회합니다.
2. 날짜나 일정 종류로 검색하고 결과 또는 결과 없음 안내를 확인합니다.
3. 관리자는 인증한 후 학교가 공개를 승인한 내용만 등록·수정하거나 필요할 때 삭제합니다. 등록과 수정 결과는 즉시 공개됩니다.
4. 저장 성공 여부를 확인하고, 공개 화면에서 변경 결과를 확인합니다.

## 7. 인수 조건

| ID | 조건 | 확인 방법 |
|---|---|---|
| AC-1 | 로그인하지 않은 방문자는 승인된 공개 자료만 조회할 수 있다. | 공개 API와 화면의 결과를 승인된 시험 자료와 대조한다. |
| AC-2 | 날짜 검색은 선택 날짜에 해당하는 자료만, 종류 검색은 해당 종류만 반환한다. 두 조건을 함께 지정하면 둘 다 만족하는 자료만 반환한다. | 다른 날짜·종류와 여러 날에 걸친 시험 일정으로 각 검색과 조합을 확인한다. |
| AC-3 | 결과가 없으면 안내를 표시한다. | 결과가 없는 날짜와 종류로 검색한다. |
| AC-4 | 320 CSS 픽셀 너비에서 목록과 검색을 가로 스크롤 없이 사용할 수 있다. | 해당 너비의 브라우저 화면에서 확인한다. |
| AC-5 | 검색과 관리 화면의 주요 동작을 키보드로 사용할 수 있고 입력 요소에 접근 가능한 이름이 있다. | 키보드와 브라우저 접근성 검사 도구로 확인한다. |
| AC-6 | 관리자만 자료를 등록·수정·삭제할 수 있다. | 미인증 요청과 관리자 권한이 없는 시험 계정의 요청, 권한을 회수한 계정의 요청을 직접 보내 거부되는지 확인한다. 관리자 요청은 성공해야 한다. |
| AC-7 | 저장된 진행 중·예정 자료는 새로고침, 다른 기기 접속, 화면 재배포 후에도 남는다. | 관리자 화면에서 자료를 저장하고 각 상황에서 내용이 유지되는지 확인한다. |
| AC-8 | 지난 일정은 시간 경과만으로 자동 삭제되지 않고 조회할 수 있다. 종료일 당일은 아직 지나지 않은 일정이다. | 시험 환경에서 종료일 당일과 다음 날의 DB 자료 및 날짜 검색 결과를 비교한다. |
| AC-9 | 저장·조회 실패 시 성공이나 결과 없음으로 표시하지 않고 오류를 알린다. | 데이터베이스 또는 네트워크 오류를 시험 환경에서 발생시켜 확인한다. |
| AC-10 | 학교 지정 검토자가 자료를 확인·승인하고 복구 절차를 시험하기 전에는 공개하지 않는다. | 승인 기록과 백업에서 복구한 시험 결과를 확인한다. |

## 8. 미결정 사항

운영 전에 학교와 다음을 결정합니다.

- 공개 승인자와 체크리스트, 관리자 인증 방식과 계정 발급·권한 회수 절차
- 학년 표시 여부와 공개할 상세 정보 수준
- 지난 자료의 보존 기간, 정정·삭제 절차, 관리자 작업 기록의 보존 범위
- 학교 일정의 기준 시간대
- 데이터베이스 서비스와 요금·무료 한도, 백업·복구 담당자와 시험 주기, 백업 주기·보존 기간, 허용 가능한 데이터 손실·복구 시간
- 학교 이름·로고 사용 허가, 문의처와 접근성·개인정보 처리 기준
